## 1. プロジェクト概要

1日に食べたものを入力すると、不足している栄養素と、それを補うための食品・レシピを提案してくれる、
ダイエット中の人向けの栄養管理アプリ。

- 開発フェーズ: 要件定義完了、実装フェーズ開始前
- リポジトリ構成: Next.js（App Router）+ Supabase の Starter Kit をベースに構築
- 想定デプロイ先: Vercel + Supabase

---

## 2. アプリのゴール（WHO / WHAT / HOW）

- **WHO（誰のためのアプリか）**
  ダイエット中で、自分の食事内容を自分で記録・管理したい本人。
  （高齢家族の食事を気にかける人、という別ユーザー像も初期検討時に挙がったが、MVPのスコープからは除外し、本人利用に一本化している。）

- **WHAT（何を提供するか）**
  食べたものを入力するだけで、その日の栄養素の過不足（ビタミン・鉄分など栄養素レベル）を可視化し、
  不足を補うための具体的な食品・一品料理を提案する。

- **HOW（どう体験させるか）**
  - 毎食その都度、スマホから気軽に記録できる（自由文章入力 or リストからの選択）
  - 1日の終わりに、その日の栄養状態をまとめて振り返る
  - 過去の記録も一覧・グラフでいつでも振り返れる

---

## 3. ターゲットユーザー詳細

| 項目 | 内容 |
|---|---|
| 主対象 | ダイエット中の本人（自分で食事を入力する人） |
| 悩み・動機 | ダイエット中に栄養バランスが崩れていないか不安 |
| 利用頻度 | 毎食（1日複数回） |
| 利用デバイス | スマートフォン |
| リテラシー | プログラミング・専門知識は前提としない一般ユーザー |
| 個人設定 | 年齢・性別・身長・体重を初回登録し、これを基準に栄養必要量を算出する |

**除外した検討対象（MVPでは扱わない）**
- 高齢の家族の食事を代わりに記録する家族ユーザー（将来的に別ペルソナとして検討の余地あり。実装する場合は本ファイルのターゲットユーザー節を更新すること）

## 4. 主要機能

### 4-1. MVP（最初のリリースで必ず実装する機能）

| No | 機能 | 内容 |
|---|---|---|
| 1 | 基本情報登録 | 年齢・性別・身長・体重を登録し、個人ごとの栄養基準値を設定する |
| 2 | 食事入力 | ①自由文章入力（例:「ご飯、鮭の塩焼き、味噌汁」）②あらかじめ用意された食品リストからの選択、の2方式に対応 |
| 3 | 栄養不足判定 | 1日単位で、ビタミンB1・鉄分などの栄養素レベルで過不足を判定する（食事ごとのリアルタイム判定ではない） |
| 4 | 補う食品・レシピ提案 | 不足栄養素に対し、食品名だけでなく「こんな一品を追加すると良い」というレシピ・料理名レベルで提案する |
| 5 | 記録の振り返り | 過去の食事内容・判定結果を一覧およびグラフで確認できる |
| 6 | 認証・ユーザー管理 | Supabase Auth を用いたログイン／サインアップ（Starter Kit に実装済みの機能を流用） |

### 4-2. 将来機能（MVP後に追加検討する機能）

| No | 機能 | 内容 | 保留理由 |
|---|---|---|---|
| 1 | 写真での食品認識 | 写真を撮るだけで食事を記録できる | 画像から食品を判定する高度な仕組み（画像認識）が必要なため、初期リリースでは見送り |

**将来機能を追加する際のルール**: 新しい機能候補が出た場合は、まずこの表に「保留理由」とともに追加し、MVPに含めるかどうかをユーザーと合意した上で 4-1 に移動すること。

## 5. UI/UX方針

- **対象ユーザーの前提知識**: 専門用語（栄養学・技術用語）を避け、平易な言葉で表示する
- **入力の手軽さを最優先**: 毎食入力する前提のため、入力までのタップ数・画面遷移は最小限にする
- **判定結果の分かりやすさ**: 「何が」「どれくらい」不足しているかを一目で分かる表現にする（数値の羅列だけでなく、一言コメント＋具体的な提案をセットで見せる）
- **提案は行動に直結する形で**: 「鉄分が不足しています」で終わらせず、「レバーやほうれん草がおすすめ」「こんな一品を追加すると良い」まで必ずセットで提示する
- **振り返り体験**: 一覧とグラフの両方を用意し、直近の状態と傾向の両方を把握できるようにする
- **デバイス**: スマートフォンでの利用を最優先（レスポンシブ対応必須、PC表示は優先度低）

## 6. 技術仕様

本プロジェクトは Next.js + Supabase Starter Kit をベースにしている。既存の構成を尊重し、独自の技術要素を無闇に追加しないこと。

| 項目 | 内容 |
|---|---|
| フレームワーク | Next.js（App Router）、React 19、TypeScript |
| スタイリング | Tailwind CSS、shadcn/ui（`components.json` 設定済み） |
| 認証・DB | Supabase（`@supabase/ssr`, `@supabase/supabase-js`）。Cookieベースのセッション管理 |
| 既存実装済み機能 | ログイン／サインアップ／パスワード再設定（`app/auth/*`）、認証済みエリア（`app/protected/*`） |
| 環境変数 | `.env.local` に Supabase の URL・公開キーを設定（`.env.example` 参照） |
| ディレクトリ構成 | `app/`（ルーティング・画面）, `components/`（UIコンポーネント、`components/ui/` は shadcn/ui）, `lib/supabase/`（Supabaseクライアント） |
| デプロイ | Vercel（Supabase Vercel Integration 利用） |

**決定済みの技術要素**（2026-08-15、データ設計フェーズにて決定。詳細は `docs/data-design.md` 参照）
- 栄養素データベース: 公的食品成分データベース（日本食品標準成分表 等）を取り込む
- 栄養必要量の算出基準: 厚生労働省「日本人の食事摂取基準」を採用。身長・体重は基礎代謝算出にのみ使用
- 自由文章入力から栄養素データへの変換: 食品マスタとの文字列マッチング
- レシピ・料理名の提案ロジック: 食品成分DBには含まれないため、手動キュレーションで初期データを用意

**決定済みの技術要素（追加分）**（2026-08-16、未確定事項の解消にて決定。詳細は `docs/data-design.md` 参照）
- 食品成分DBの入手元・形式: 文部科学省「日本食品標準成分表2020年版（八訂）増補2023年」。同省サイト配布のExcelをCSV変換してSupabaseにseed。政府データにつき二次利用可（出典明記が必要）。改訂は数年に1度のため自動同期は作らず手動更新
- `foods`のカテゴリ・正規化方針: 成分表の食品群をそのまま `foods.category` に採用。表記ゆれは新設の `food_aliases` テーブルで吸収
- 自由文章マッチングの精度: MVPでは完全一致＋部分一致（LIKE検索）。マッチしない場合は候補リストを提示しユーザーに選ばせる
- `suggestions`の初期データ範囲: 不足しがちな栄養素5〜8種に絞り、各栄養素につき3〜5件を手動キュレーション
- `daily_nutrition_summaries`の算出タイミング: 「1日の結果画面」表示時にオンデマンド計算してキャッシュ保存（バッチ処理基盤はMVPでは作らない）

**未確定・今後決める必要がある技術要素**（実装前に要確認）
- なし（2026-08-16時点ですべて決定済み）

## 8. 成功基準

MVPが「成功した」と言えるかどうかは、以下を目安に判断する。

- ユーザーが毎食、迷わず・ストレスなく食事を記録できる（入力方法が原因で記録が続かない、という状態になっていない）
- 1日の終わりに、栄養の過不足が「何がどれくらい足りないか」を専門知識なしで理解できる
- 提示された食品・レシピの提案が、次の食事の行動に実際につながる（提案止まりで終わらない）
- 過去の記録を振り返ることで、ユーザー自身が栄養状態の傾向に気づける

**未確定**: 具体的な数値目標（例: 継続率◯%、栄養充足率◯%改善など）は、リリース後の実データを見て設定する。定義でき次第、本セクションに追記すること。
